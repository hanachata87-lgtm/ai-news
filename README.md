# 生成AI 最新情報あつめ

生成AIの新着情報を **1日2回 (日本時間 7:00 / 19:00) 自動で集めて**、
スマホやタブレットのブラウザから読めるページを作るしくみです。

> **このリポジトリは公開 (public) です。**
> GitHub Pages で閲覧ページを配信するために公開にしています。
> パスワードや個人情報はここに置かないでください
> (集めているのは、誰でも読める公開記事へのリンクだけです)。

パソコンの電源が入っていなくても、GitHub のサーバー (GitHub Actions) が
勝手に動いて情報を貯めてくれます。あなたは好きなときにページを開くだけです。

## 集めている情報

| カテゴリ | 内容 |
|---|---|
| **Claude** | Claude / Anthropic の新機能・料金・使い方の工夫 |
| **Copilot** | Microsoft 365 Copilot の新機能・できること |
| **その他AI** | ChatGPT, Gemini など、その他の生成AIの大きな動き |

## ファイルの役割

| ファイル | 役割 | あなたが触るか |
|---|---|---|
| `feeds.yml` | **情報源の一覧**。増やす・減らすときはここを編集する | ◎ よく触る |
| `articles.json` | 集めた記事の保管場所。自動で書き換わる | × 触らない |
| `collect.py` | 情報源から新着記事を集めるプログラム | × 触らない |
| `render.py` | 集めた記事から閲覧ページを作るプログラム | × 触らない |
| `template.html` | 閲覧ページの見た目のひな型 | △ 見た目を変えたいとき |
| `check_feeds.py` | 情報源がちゃんと取得できるか確認するプログラム | △ 確認したいとき |
| `requirements.txt` | 必要な Python ライブラリの一覧 | × 触らない |

できあがったページは **`docs/index.html`** です。これが GitHub Pages で公開されます。

## A. スマホから見る

GitHub Pages を有効にすると、次のURLで見られます。

```
https://hanachata87-lgtm.github.io/ai-news/
```

ホーム画面に追加しておくと、アプリのように開けます。

- **iPhone (Safari)**: 共有ボタン → 「ホーム画面に追加」
- **Android (Chrome)**: 右上の︙ → 「ホーム画面に追加」

### ページでできること

- 新しい順に並ぶ。**未読には左端に色の点**が付き、既読は薄くなる
- **カテゴリ** (Claude / Copilot / その他AI) と **情報源** で絞り込める
- **キーワード検索** ができる (スペース区切りで複数指定可)
- 「**未読のみ**」で未読だけ表示、「**すべて既読**」で表示中をまとめて既読にできる
- 一番上に **最終更新日時** が出る。26時間以上更新がないと警告が出るので、
  止まったことに気づけます

> 既読の情報は **その端末のブラウザの中だけ** に保存されます。
> スマホで読んだ記事は、タブレットでは未読のままです (サーバーには何も送りません)。

## B. 情報源を増やす・減らす

`feeds.yml` を編集します。**GitHub のサイト上で直接編集するのがいちばん簡単です。**

1. GitHub で `feeds.yml` を開く
2. 右上の **鉛筆マーク (Edit this file)** を押す
3. 書き換えて、下の **Commit changes** を押す

### 減らすとき

消さずに `enabled: true` を `enabled: false` に書き換えます。あとで戻せます。

```yaml
  - name: GIGAZINE (日本語・AI関連のみ)
    url: https://gigazine.net/news/rss_2.0/
    category: other
    enabled: false        # ← これで取り込まれなくなる
```

### 増やすとき

`feeds:` の一覧の最後に、同じ形で追記します。

```yaml
  - name: 好きな情報源の名前
    url: https://example.com/feed.xml
    category: other       # claude / copilot / other のどれか
    enabled: true
```

AI以外の記事も流れてくるサイトは、`include_keywords` を付けると
そのキーワードを含む記事だけを取り込みます。

```yaml
    include_keywords: ["AI", "Claude", "Copilot", "生成"]
```

`AI` のような英字だけのキーワードは **単語として現れたときだけ** 一致します
(`available` や `email` の中の `ai` には反応しません)。
`生成` のような日本語は、文の途中に含まれていれば一致します。

### 取り込む量を調整したいとき

`feeds.yml` のいちばん上にある `settings:` を書き換えます。

| 設定 | 初期値 | 意味 |
|---|---|---|
| `ignore_older_than_days` | 30 | 公開から何日以内の記事を取り込むか。**多すぎると感じたら小さくする** |
| `max_entries_per_feed` | 40 | 1つの情報源から1回に取り込む最大件数 |
| `max_age_days` | 180 | 何日分ためておくか (これより古い記事は消える) |
| `max_articles` | 1500 | ためておく記事の最大件数 |
| `summary_length` | 220 | 概要の文字数 |

### 公式のRSSが無いサイトを追いかけたいとき

**Google ニュースの検索フィード**が使えます。URLの `q=` のうしろに検索したい言葉を入れます。

```
https://news.google.com/rss/search?q=検索したい言葉&hl=ja&gl=JP&ceid=JP:ja
```

- 日本語や記号を入れるときは、そのまま書くと動かないことがあります。
  `"..."` で囲んだ複数語の検索は `%22Microsoft+365+Copilot%22` のように、
  空白を `+`、`"` を `%22` に置き換えてください
- 英語の情報も取りたいときは末尾を `hl=en-US&gl=US&ceid=US:en` にします

**GitHub のリリース情報**も、どのリポジトリでも次の形で取れます。

```
https://github.com/（作者名）/（リポジトリ名）/releases.atom
```

### 編集したあとの確認

`feeds.yml` を保存すると、GitHub が自動で2つの確認をします。
リポジトリの **Actions** タブで結果を見られます。

- **Check feeds** … 情報源が本当に取得できるか確認する (取れないものがあると赤いバツ)
- **AI news** … 実際に記事を集めてページを作り直す

赤いバツが出たら、その実行を開いてログを見ると、どの情報源がなぜ失敗したかが書いてあります。

## C. パソコンで動かす (任意)

普段はクラウドで自動実行されるので、この作業は必要ありません。
手元で試したいときだけ使ってください。

```powershell
# 初回のみ: 必要なライブラリを入れる
pip install -r requirements.txt

# 情報源が取得できるか確認する
python check_feeds.py

# 記事を集める → ページを作る
python collect.py
python render.py
```

できた `docs/index.html` をダブルクリックすると、ブラウザで開けます。

## D. 動かなくなったときの調べ方

1. GitHub の **Actions** タブを開く
2. 左側の **AI news** を選び、一番上 (最新) の実行を開く
3. 赤いバツが付いた項目を開くとログが出ます

| ログに出ること | 意味 |
|---|---|
| `→ 成功: 30 件中 3 件が新着` | 正常。3件の新しい記事が増えた |
| `→ 失敗: HTTP 404` | その情報源のURLが変わったか無くなった。`feeds.yml` を直す |
| `→ 失敗: タイムアウト` | 相手のサーバーが重いだけ。次回直ることが多い |
| `[エラー] すべての情報源の取得に失敗しました` | GitHub 側の通信障害の可能性。しばらく待つ |

1つや2つの情報源が失敗しても、**残りの情報源は普通に取り込まれます**。
失敗した情報源は閲覧ページの上部にも表示されます。

### 自動実行が止まってしまうことがあります

GitHub には「**60日間リポジトリに何も動きがないと、定期実行を自動で止める**」という
決まりがあります。止まると Actions タブに再開ボタンが出るので押してください。
このしくみは記事が増えるたびに自動でコミットするので、普通は止まりません。
